Akteure und Beziehungen im PoC

Kubernetes-Cluster (k3s)

API-Server

signiert Tokens mit privatem Schlüssel

Pod „consumer“

Token liegt als Datei im Container

issuer-web (nginx)

Discovery-Dokument + JWKS per HTTPS

Validator (Spring Boot)

externer Dienst, außerhalb des Clusters

kurzlebiges Token (10 min), nur für den Validator

einmalig: Bootstrap kopiert Schlüssel

GET /whoami mit Bearer-Token

HTTPS: Discovery + JWKS, 5 min Cache

Validator spricht nie mit dem API-Server

  • Der Pod bekommt sein Token automatisch vom Cluster – kein Secret im Deployment
  • issuer-web veröffentlicht nur öffentliche Metadaten, entkoppelt vom API-Server
  • Der Validator besitzt kein Cluster-Credential und braucht keinen Netzweg in den Cluster
Vier Akteure: API-Server stellt aus, Pod nutzt das Token, issuer-web veröffentlicht die öffentlichen Schlüssel, Validator prüft. Die gestrichelte Linie passiert nur einmal beim Start (Bootstrap). Wichtigste Botschaft: Zwischen Validator und API-Server gibt es keine Verbindung.
