Aufbau: Startreihenfolge mit docker compose up

1

server (k3s)

  • Kubernetes-Cluster in einem Container
  • Token-Issuer zeigt auf issuer-web
  • davor: Lab-CA und Signaturschlüssel erzeugt

2

bootstrap

  • legt Namespaces, ServiceAccounts und Pods an
  • übergibt dem jwks-publisher sein Client-Zertifikat

3

issuer-web

  • jwks-publisher lädt Discovery + JWKS per mTLS hoch
  • nginx liefert sie öffentlich per HTTPS aus

4

validator

  • lädt Discovery + JWKS
  • startet nur, wenn der Issuer passt

5

demo

  • auf Abruf gestartet
  • End-to-End-Test: Gut- und Fehlerfälle
  • Auf dem Host nur Docker + Compose v2 – alles andere läuft in Containern
  • Reihenfolge über Compose-Abhängigkeiten: Der nächste Dienst startet erst, wenn der vorige bereit bzw. erfolgreich beendet ist
  • Weil der Cluster schon mit externem Issuer startet, trägt jedes Token iss = https://issuer-web
Ein docker compose up baut das komplette Lab. Der bootstrap-Container läuft einmal durch und beendet sich. Danach hält der jwks-publisher im Cluster issuer-web aktuell, auch bei einer Schlüsselrotation.
