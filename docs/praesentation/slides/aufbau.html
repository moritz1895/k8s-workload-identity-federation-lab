Anhang: Startreihenfolge mit docker compose up

1

pki-init, sa-keys

  • Lab-CA und Zertifikate aller Dienste
  • Signaturschlüssel des Clusters

2

server (k3s)

  • Kubernetes-Cluster in einem Container
  • Token-Issuer zeigt auf issuer-web

3

bootstrap

  • legt Namespaces, ServiceAccounts und Pods an
  • gibt dem Publisher sein Client-Zertifikat

4

issuer-web

  • Publisher lädt Discovery + JWKS per mTLS hoch
  • nginx liefert sie per HTTPS aus

5

Dienste

  • keycloak + gateway
  • service-r (Dienst R)
  • validator (Variante)
  • Auf dem Host nur Docker + Compose v2 – alles andere läuft in Containern, in drei getrennten Netzen
  • Reihenfolge über Compose-Abhängigkeiten: Ein Dienst startet erst, wenn seine Vorgänger bereit bzw. erfolgreich beendet sind
  • Keycloak startet erst, wenn issuer-web bereit ist; die Cluster-Schlüssel lädt es bei Bedarf und cacht sie
Ein docker compose up baut das komplette Lab. pki-init und sa-keys laufen einmal und beenden sich, ebenso bootstrap. Danach hält der Publisher im Cluster issuer-web aktuell, auch bei einer Schlüsselrotation. service-r braucht beim Start nur sein Zertifikat; die Discovery bei Keycloak macht es erst beim ersten Token.
