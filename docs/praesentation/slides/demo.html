Live-Demo

# einmalig

cp .env.example .env

# Lab starten

docker compose up -d --build

# Token-Austausch und Zugriff auf Dienst R

docker compose run --rm demo authz

# Veröffentlichung über den Ingress, nur lesend

docker compose run --rm demo

# alles, inkl. Härtung, Netztrennung, Schlüsselwechsel

tools/run-all-checks.sh

Was die Demo zeigt

  1. consumer tauscht sein ServiceAccount-Token gegen ein Access-Token
  2. consumer → Dienst R: 200
  3. Recht fehlt: 403; unbekannte Workload: abgelehnt
  4. Keycloak-Administration über das Gateway nicht erreichbar
  5. Issuer-Endpunkt nur lesend: PUT, POST, DELETE abgelehnt, fremder Host abgewiesen
Voraussetzung auf dem Rechner ist nur Docker mit Compose v2; aufräumen mit docker compose down -v. Dienst R ist vom Host nur per HTTPS erreichbar (Port 18081, Zertifikat der Lab-CA). Die Keycloak-Admin-Konsole läuft nur bei Bedarf über einen eigenen Proxy. run-all-checks.sh dauert länger, weil es den API-Server für den Schlüsselwechsel in zwei Phasen zweimal neu startet. Zum Nachvollziehen Schritt für Schritt gibt es die animierte Seite „WIF-Ablauf Schritt für Schritt“.
