Optionale Folie: ein Ausblick, kein Teil des PoC. SPIFFE ist ein Standard für Workload-Identitäten, SPIRE seine Referenzimplementierung. Der SPIRE-Server übernimmt die Rolle des API-Servers als „Passamt“; der Pass heißt SVID und trägt eine SPIFFE-ID wie spiffe://bank/ns/wif-demo/sa/consumer. Auf jedem Node und jedem anderen Host läuft ein SPIRE-Agent. Er weist sich beim Server aus – auf Bare Metal zum Beispiel über das TPM – und prüft lokal, welcher Prozess anfragt: im Cluster über das kubelet, auf dem Host über Benutzer, Pfad oder Hash des Programms. Welche Workload welche SPIFFE-ID bekommt, steht in Registrierungseinträgen; die können in Git liegen und brauchen dieselbe Genehmigung durch den Fachbereich wie heute die Deploy-Rechte. Keycloak bringt einen SPIFFE-Identity-Provider mit und holt die Prüfschlüssel über den Bundle-Endpoint. Discovery-Pod und Traefik-Route für den Aussteller entfallen dann. Den Signierschlüssel hält jetzt der SPIRE-Server; die Fragen von der Folie zum Signierschlüssel gelten für ihn genauso. Lohnt sich vor allem, wenn Anwendungen außerhalb von Kubernetes dazukommen, mTLS gefordert ist oder mehrere Cluster zusammenspielen. Der SPIRE-Server kann auch selbst im Cluster laufen.
